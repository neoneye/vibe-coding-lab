How two browsers talk to each other without a server in between

WebRTC lets one browser send video, sound, messages and files straight to another. This page shows how the connection is made, step by step with a real one, and then lets you connect two browsers by hand and use it.

1Why it is hard

A web page can call out to a server, but nothing can call a web page. Your computer usually sits behind a router that shares one public address among every device in the house, and the router only lets in traffic that answers something sent out first. Two browsers that both sit behind such routers cannot simply dial each other: neither knows the other's address, and neither router would let a stranger in.

2The three things a connection needs

A description of each side

What each browser wants to send (data, sound, video, in which formats) and the fingerprint of the encryption key it will use. This is a block of text called SDP. The first one is the offer, the reply to it is the answer.

Addresses to try

Every way the browser might be reached: its address on the local network, and its public address as seen from outside. Each is an ICE candidate. The two browsers then try every pair until one gets through.

A way to pass those across

The offer and answer have to reach the other side before any connection exists. This is signalling, and WebRTC leaves it entirely to you. Most sites use a server for it. On this page it is you, with copy and paste.

The trick that gets through the routers: once both sides know each other's candidates, both start sending small test packets to each other at the same moment. Each router sees its own computer sending out first, so it lets the replies in. This is often called hole punching.

    File sharing

    A second data channel carries files. A file is cut into 16 KB pieces, sent in order and put back together on the other side. The sender waits whenever the channel's queue fills up, so a large file does not swamp the connection.

    Camera and sound

    Video and sound do not use data channels. They travel as media tracks, which may drop a late frame instead of waiting for it, and adjust their quality to the connection. Room for one sound track and one video track each way was agreed in the offer and answer, so switching the camera on later needs no new exchange of codes.

    7Things worth knowing

    A code is for one connection

    The offer and answer belong to one attempt. If it fails or you close the page, start again with fresh codes.

    Why making a code takes a moment

    The browser waits until it has found all its addresses, so that they fit in one code. Sites with a signalling server send each address as it is found instead, which is faster.

    Two is easy, ten is not

    Every pair needs its own connection. Calls with many people usually send everything through a server in the middle, which is no longer peer to peer.

    Your address is visible

    The other browser learns an address it can reach you at. That is how a direct connection works. Browsers hide local addresses behind random .local names where they can.
