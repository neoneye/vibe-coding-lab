# MIT SCHEME-79 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build `mit-scheme-79/index.html`, a cycle-level simulator of the 1979 SCHEME-79 Lisp chip running the microcode from AI Memo 559, as Silicon Observatory No. 005.

**Architecture:** One self-contained HTML page. `<script id="shared-code">` holds the engine: the memo's micro-LISP listing as text, a micro-LISP → microcode compiler, a cycle-level `Chip`, a statement-level `ReferenceMachine` used as the test oracle, `Memory`, and a `Host` that plays the part of the interface board (Scheme → S-code translator, loader, interrupts, console). A second `<script>` holds the UI. `test.mjs` runs `Scheme79Tests.run()` under Node.

**Tech Stack:** Vanilla JS, inline SVG and canvas, no dependencies. Node ≥ 18 for tests.

## Global Constraints

- Single `index.html`, no network, no dependencies; follows `acorn-arm1/index.html` layout and palette (Silicon Observatory template).
- Engine in `<script id="shared-code">`; `node mit-scheme-79/test.mjs` exits 0 when all tests pass.
- The micro-LISP listing is the memo's (AIM-559 appendix p.29–43), transcribed verbatim, including `primitive-displacement-add1` as printed.
- Everything not from the memo is labelled on the page as the page's own: the compilation to PLA states and nano-ops, the FRAME/DISPLACEMENT split, the S-code translator, the console, the host.
- Header facts: 1979 · 32-bit word · ≈1 MHz · transistors "not published".
- Word layout: bit 31 mark, bits 30–24 type, bits 23–0 data; displacement = bits 23–12, frame = bits 11–0.
- Demo order and count as the spec lists (8 demos).

## Reconstruction decisions (fixed here, used by every task)

**Registers** (index → name): 0 NIL, 1 MEMTOP, 2 NEWCELL, 3 EXP, 4 VAL, 5 ARGS, 6 DISPLAY, 7 STACK, 8 RETPC (retpc-count-mark), 9 IA (intermediate-argument). Aliases: scan-up→NEWCELL, scan-down→EXP, stack-top/rel-tem-2→VAL, leader/rel-tem-1→ARGS, node-pointer→DISPLAY.

**Field masks:** TYPE `0x7F000000`, ADDR `0x00FFFFFF`, DISP `0x00FFF000`, FRAME `0x00000FFF`, WHOLE `0xFFFFFFFF`. Fielded registers (EXP NEWCELL VAL RETPC STACK) have no mark storage: a "whole" load into them uses `TYPE|ADDR` and bit 31 stays 0. MEMTOP ARGS DISPLAY IA store all 32 bits. NIL always reads 0.

**Bus sources:** a register; `NEWCELL+1` (address field incremented, type kept); `EXP−1` (same, decremented); `PADS` (memory word on READ, interrupt vector on READ-INTERRUPT); `LIT` (the micro-word's literal in the type field, zero data). Sense lines: bus mark bit, bus type-not-pointer (type bit 6), bus frame = 0, bus displacement = 0, bus address = 0, VAL type = bus type, VAL = bus (type and address), NEWCELL address = bus address.

**Memory writes** store `(bus & 0x7FFFFFFF) | (MARK1 ? 1<<31 : 0)`. So RPLACA and RPLACD clear the mark, as the memo says (p.32).

**Nano-ops** (`*` = the micro-word's FROM or TO):

| op | cycles |
|---|---|
| MOVE | `* → *` |
| ALE | `from* → bus, ALE` |
| READ / READ-CDR | `PADS → to*, READ [CDR]` (may branch) |
| WRITE / WRITE-CDR / WRITE-MARK / WRITE-CDR-MARK | `from* → PADS, WRITE [CDR] [MARK1]` |
| DO-CAR / DO-CDR | `from* ALE` · `PADS → to*, READ [CDR]` |
| DO-RESTORE | `STACK ALE` · `PADS → to*, READ` · `PADS → STACK(type+addr), READ CDR` |
| DO-SAVE | `NEWCELL+1 → RETPC.addr` · `RETPC → NEWCELL.addr` · `MEMTOP → bus, GC-CHECK` · `NEWCELL ALE` · `from* WRITE` · `STACK WRITE CDR` · `NEWCELL → STACK(type+addr)` |
| DO-CONS | as DO-SAVE but the CDR comes from IA and the result goes to `to*` |
| SET-MARK / CLR-MARK / SET-CDR-MARK / CLR-CDR-MARK | `from* ALE` · `PADS → IA, READ [CDR]` · `IA WRITE [CDR] [MARK1]` |
| INC-NEWCELL | `NEWCELL+1 → RETPC.addr` · `RETPC → NEWCELL.addr` |
| DEC-EXP / DEC-FRAME / DEC-DISP | `EXP−1 → RETPC.addr` · `RETPC → EXP.{addr, frame, disp}` |
| INC-TO-VAL / DEC-TO-VAL | `NEWCELL+1 → VAL.addr` / `EXP−1 → VAL.addr` |
| READ-INT | `PADS → to*, READ-INTERRUPT` |
| CLEAR-GC | clears the GC-needed flip-flop |

GC-CHECK sets GC-needed when NEWCELL's address equals the bus address.

**Micro-word:** `{ state, from, to, toMask, nano, lit, next, line }`, where `next` is one of: `{goto:s}`, `{branch:sense, base}` (the next state is `base | senseBit`, so both targets sit at an even/odd pair), `{dispatch:true}` (next state = bus type), `{dispatchInt:true}` (`0o777` if an interrupt is requested, else the bus type), or `{halt}`. A branch or dispatch reads the sense lines on the micro-word's last cycle.

**State assignment:**
- `deftype` routines sit at their octal type code; `boot-load` at `0o776`, `process-interrupt` at `0o777`.
- `defreturn` routines, and the targets of `micro-call`, take free codes in `0o27–0o77`, so every return address is a pointer type (p.31) and fits the 7-bit type field.
- Every other state takes the lowest free slot.
- A branch allocates an even/odd pair; a target whose head already has a state gets a copy of its head micro-word at the pair slot (p.15).
- Test: the highest state is ≤ `0o777`.

**Compilation rules:**
- A nested operand is computed into its final target when that target is not also an operand, otherwise into IA.
- `&cons` puts its CDR operand in IA.
- RPLACA and RPLACD become two micro-words, ALE then WRITE, as the memo's MARK-NODE-2 shows.
- A `go-to` merges into the previous micro-word's `next`. A branch arm that is only a `go-to` targets that label directly.
- `(&set-type R CONST)` uses LIT.
- `micro-call L T` is `LIT T → RETPC.type` then goto L. `micro-return` is a dispatch on RETPC.
- `eval-exp-popj-to T` is `LIT T → STACK.type`, then a dispatch-with-interrupts on EXP.

**Host memory map:**
- Node 0: NIL, with the obarray list in its CDR.
- Node 1: CAR = MEMTOP as an immediate.
- Nodes 2…: the symbols `*boot*`, `*gc-handler*`, `*interrupt-handler*`, then the other symbols, then the obarray cells, then quoted data and code.
- I/O: `IO_CHAR = 0xFFFFF0` and `IO_NUMBER = 0xFFFFF1`. An RPLACA onto either prints; a read returns 0.
- A read or write at or above the physical size, other than I/O, faults and halts.
