The 33 Invisible Characters

ASCII has 128 codes, and 33 of them print nothing. They were made to run teleprinters: ring a bell, return the carriage, switch on a tape punch, end a transmission. This page tells where each one came from, whether anything still uses it, and lets you try every one of them.

The story

Before screens, a computer terminal was a typewriter wired to a line: a teleprinter. Letters arrived as codes and were printed. Everything else the machine could do (go back to the margin, roll the paper, ring for the operator, start the tape reader) also had to arrive as a code, because the wire was the only way in. Those codes are the control characters, and their names still describe the machinery.

  1. 1870sBaudot's five-unit code. Émile Baudot's printing telegraph sent each character as five on/off units, 32 combinations, with a letters/figures shift to fit more. Shifting is the first "control" idea: a code that changes what the next codes mean.
  2. 1901Murray's tape code. Donald Murray rearranged the code for a typewriter-style keyboard that punched paper tape, and added codes that print nothing: carriage return and line feed. The format effectors were born.
  3. 1920s–30sITA2, the telex alphabet. The international standard had a blank (null) code, CR, LF, a bell, and WRU, "who are you?", which made the distant machine send back its identity from an answer-back drum. The all-holes code (letters shift) was harmless, so operators erased mistakes on tape by overpunching them with it.
  4. 1963ASCII. The American Standards Association published a 7-bit code, X3.4-1963. The committee, with people from telegraphy, computing and business machines, gave the first 32 codes to control functions and put DEL, all seven bits set, at 127. The Teletype Model 33, launched the same year and cheap, made ASCII the language of minicomputers and later of Unix.
  5. 1967The names we use. The revision added lower case and settled the control names (WRU became ENQ). ECMA-6 and ISO 646 made the same 33 international.
  6. 1976–78Escape sequences. Instead of spending more codes, a terminal could take ESC followed by ordinary characters. ECMA-48 (1976) and ANSI X3.64 standardised them; the DEC VT100 (1978) made them universal, and every terminal emulator still speaks that dialect.
  7. 1991Unicode. The 33 keep their numbers as U+0000–U+001F and U+007F, 32 more (the C1 controls) sit at U+0080–U+009F, and the Control Pictures block gives each a visible stand-in: ␀ ␁ ␂ … ␟ ␡. This page uses them.

Most of the 33 were designed for a world of leased lines and mechanical printers that is gone. What survived falls into three kinds: the ones every text still needs (tab, newline, the bell, escape), ones that became something else because they sit under a Ctrl key, and ones that found a niche as delimiters that no text can contain.

Where they sit in the table

ASCII is drawn as 8 columns of 16. The column is the top three bits, the row the bottom four. Columns 0 and 1, where the top two bits are 00, hold all 32 controls, so a machine could tell "act" from "print" by looking at two bits. Space opens column 2, upper case lives in column 4–5 and lower case in 6–7, 32 apart, so changing case is flipping one bit.

DEL is the exception, alone at 127 because on paper tape it had to be all holes. A hole can't be filled back in, so any character can be turned into DEL by punching the rest of its holes, and every reader was built to skip it. NUL, no holes at all, is blank tape.

The Ctrl key on the Model 33 cleared the bit worth 64 of whatever key you held, so Ctrl+G sent 0000111 instead of 1000111: BEL. Keyboards still work that way, and it gives caret notation, the way terminals print controls: ^G for BEL, ^[ for ESC, ^@ for NUL, and ^? for DEL (0x3F with the 64 bit set is 0x7F). Lab 4 · XON and XOFF

A computer sends at 120 characters a second to a printing terminal that manages 30 and has a 32-character buffer. With flow control the printer sends XOFF (DC3) when its buffer is three-quarters full and XON (DC1) when it has room again. The computer takes a few characters to react, which is why XOFF goes out before the buffer is full. Without flow control, whatever doesn't fit is lost.

Lab 5 · XMODEM: SOH, ACK, NAK, EOT, CAN and SUB

Ward Christensen's 1977 file transfer protocol, written for CP/M machines talking through modems, has a vocabulary of almost nothing but control characters. The receiver asks with NAK, each 128-byte block starts with SOH and ends with a one-byte checksum, ACK means “good, next”, NAK means “again”, EOT ends the file and CAN CAN gives up. The last block is padded with SUB, the CP/M end-of-file mark. Add noise to see blocks resent.

Lab 6 · Framing a serial line: STX, ETX, ETB, ENQ, DLE, SYN

Blood analysers in hospital labs send results to the lab computer with a protocol from 1991 (ASTM E1381, now CLSI LIS01-A2) that is all transmission controls. The instrument asks for the line with ENQ, sends each record in frames STX frame-number text ETB or ETX, two hex checksum digits, CR LF, waits for ACK after each frame, and ends with EOT. Records longer than a frame continue in the next one: those frames end in ETB. Edit the records:

If a message is framed STX … ETX, the data must never contain the byte 0x03. Binary data can. Bisync's answer was DLE: frame with DLE STX … DLE ETX, and send any DLE in the data twice. A lone DLE followed by ETX can then only mean “end”.

Asynchronous lines wrap every character in start and stop bits. Synchronous lines (Bisync, 1960s) sent a continuous stream of bits with no markers, so the receiver didn't know where bytes began. Senders put SYN SYN (0x16 0x16) in front of every message, and the receiver slid a 16-bit window along the stream until it matched, then counted in eights from there.

Lab 7 · Separators in real data: SOH, GS, RS, US

FIX, the Financial Information eXchange protocol (1992), is how brokers, banks and exchanges send orders to each other. A message is tag=value pairs, each ended by SOH. BodyLength (9) counts the bytes after it up to the checksum, and CheckSum (10) is the sum of every byte before it, modulo 256. Logs usually print SOH as |.

The DataMatrix on a medicine pack and the GS1-128 label on a pallet hold several fields, each starting with a numeric Application Identifier. Some fields have a fixed length (a GTIN is always 14 digits); others, like batch and serial numbers, don't, so the encoder ends them with a special FNC1 symbol, which the scanner hands to software as GS (0x1D). The human-readable line in brackets doesn't need it, because the brackets do the job.

Library catalogues have exchanged records in MARC since the 1960s, in the ISO 2709 structure, and still do. It uses three separators: US starts a subfield (followed by its letter), RS ends a field and the directory, GS ends the record. The 24-character leader and the directory give byte lengths and offsets, so a program can jump straight to field 245. Change the book:

A log of JSON values is easy to write but hard to read back if a writer crashes half way through a value, or if values span several lines. RFC 7464 (2015) puts RS in front of every JSON value. RS can never appear raw inside JSON, since control characters in strings must be escaped, so a reader can always find the next value and skip a broken one.
